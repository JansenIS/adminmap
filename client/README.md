# Adminmap user desktop client

`client/` — отдельный пользовательский Tauri/Vite-проект. Он предназначен для будущей сборки в desktop-приложение и открывает все пользовательские точки входа основного adminmap-сервера через единый launcher.

## Что входит

Пользовательский launcher содержит:

- публичную карту и альтернативную публичную карту;
- hexmap;
- wiki/энциклопедию;
- летопись приказов;
- дипломатию;
- кабинет сущности;
- player-admin и приказы игрока;
- token battle screens;
- генераторы гербов, имён, городов, деревень;
- публичную генеалогию и микрокарту.

Список пользовательских точек входа хранится в `src/modules.js`.

## Выбор удалённого сервера

В клиенте есть отдельные поля для выбора сервера:

- схема: `http` или `https`;
- IP/host: например `127.0.0.1`, `192.168.1.10`, `example.org`;
- порт: например `8080`;
- base path, если проект опубликован не в корне домена.

Итоговый URL показывается в UI и сохраняется в IndexedDB. Для token-сценариев можно задать общий query string, например `token=...`.

## Данные и синхронизация

- JSON-данные карты загружаются через `/api/map/version/`, `/api/map/bootstrap/`, `/api/provinces/`;
- тайлы берутся с `/api/tiles/`;
- локальные правки провинций складываются в IndexedDB и выгружаются пакетами через `/api/changes/apply/` с `If-Match`.

## Tauri-проект

В этой папке есть собственный `src-tauri/` с отдельным `Cargo.toml`, `tauri.conf.json`, window label и bundle identifier. Это самостоятельный пользовательский Tauri-проект; он не использует HTML entrypoint второго клиента. Иконки и другие бинарные assets намеренно не добавлены в git — их можно скачать или создать в runtime/CI.

## Runtime-cache и бинарные ассеты

Runtime-cache, скачанные ассеты и созданные клиентом файлы разрешены на машине пользователя/в Tauri runtime. Ограничение касается только git-коммита: GitHub не должен получать `.exe`, иконки, тайлы, изображения и другие бинарные артефакты. Поэтому `client/.gitignore` игнорирует бинарные расширения и build outputs, но не запрещает создавать директории cache/assets/downloads во время работы клиента.

## Запуск разработки

Поднимите основной сервер из корня проекта:

```bash
php -S 127.0.0.1:8080
```

Запустите пользовательский клиент:

```bash
cd client
npm install
npm run dev
```

## Проверка без установки зависимостей

```bash
cd client
npm run check
```

## Как не скачивать `client/` при обычном pull на production-сервере

Git не умеет запретить скачивание уже отслеживаемой папки для всех пользователей через файл внутри репозитория. Для production-серверов, где desktop-клиент не нужен, включите sparse checkout один раз:

```bash
git sparse-checkout init --no-cone
printf '/*\n!/client/\n!/client-admin/\n' > .git/info/sparse-checkout
git read-tree -mu HEAD
```
